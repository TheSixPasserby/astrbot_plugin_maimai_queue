# astrbot_plugin_maimai_queue

舞萌DX / 中二节奏 机厅排卡插件（AstrBot 版），由 QFun 版 `maimai_queue` v8 移植。

在目标群或私聊中由**管理员**发送「开启排卡」即可启用，各聊天数据完全隔离（按 `unified_msg_origin` 区分），发送「关闭排卡」停止。支持舞萌/中二分机台、分游戏统计，机厅合计独立记录，跨天自动清卡。

## 安装

将本目录放入 AstrBot 的 `data/plugins/` 下，在 WebUI 插件页重载即可。无第三方依赖。

## 指令

所有指令为**纯文本消息**（无需 `/` 前缀，插件通过事件监听器自行解析）。

### 排卡指令（开启后所有人可用）

| 指令 | 说明 |
|---|---|
| `排卡帮助` | 查看完整帮助 |
| `j` / `机厅几人` | 排卡总览（舞萌 + 中二 + 合计） |
| `mai几` / `舞萌几`（几人/几卡皆可） | 查看舞萌排卡 |
| `chu几` / `中二几` | 查看中二排卡 |
| `<机厅别名>几` / `机厅几` | 排卡总览 |
| `j+n` / `j-n` / `jn` / `j=n` | 机厅合计 加/减/设置 |
| `<别名>+n` / `-n` / `=n` / `n`、`别名加n/减n/设置n` | 机厅合计 加/减/设置 |
| `mai+n` / `mai-n` / `main` / `mai=n`（`舞萌` 前缀同效） | 舞萌 加/减/设置，差值同步进合计 |
| `chu+n` / `chu-n` / `chun` / `chu=n`（`中二` 前缀同效） | 中二 加/减/设置，差值同步进合计 |
| `mai<a>chu<b>` / `chu<b>mai<a>` / `舞萌a中二b` | 一条消息同时更新两个游戏（原子校验；两段间可用 `,;.、。` 等分隔，如 `mai3，chu2`） |
| `机厅别名` | 查看已设置的别名 |

**智能匹配**：消息中带 @ 或其他文字时，包含 `mai+1` / `chu-1` 这类**带操作符**的指令也能识别；裸数字形式（如 `mai3`）仅在整条消息即指令时生效，防止「舞萌30分钟后到」被误判；超过 30 字（可配置）的长消息不参与智能匹配，防止转发/引用/长聊天误触发。

### 管理指令（仅 AstrBot 管理员）

- `开启排卡` / `关闭排卡` — 本聊天排卡开关（非管理员发送时静默忽略）
- `添加机厅别名 <别名>` / `删除机厅别名 <别名>`
- `设置机台 mai<n> chu<n>` — 如 `设置机台 mai2 chu1`；某游戏机台为 0 时该机种从总览隐藏
- `设置排卡上限<n>` — 默认 30，对舞萌/中二各自独立生效

### 行为细节

- 越界（减成负数/超上限）回复「干什么！」且不写入
- 机均为总机台数整除时显示具体值，否则显示 `商+`（如 `2+`）
- 舞萌 / 中二 / 合计三组数据各自独立记录卡数、更新时间、更新人，且各自独立跨天清零
- `mai`/`chu` 更新按差值同步进合计（合计未记录时以两游戏之和为基准）；合计上限 = 排卡上限 × 有机台的游戏数
- 全角输入兼容（`Ｊ＋２` 等同 `j+2`）、大小写兼容
- 群聊回复会 @ 操作人，私聊不带
- 识别为排卡指令后会 `stop_event()`，不再触发 LLM 或其他插件；非指令消息不受影响

### QQ 官方机器人 Markdown 排版

接入 QQ 官方机器人（`qq_official` / `qq_official_webhook` 平台）时，回复自动切换为 Markdown 排版（其他平台不受影响，始终纯文本）：

- 标题 / 加粗 / 引用块 / 分割线排版，总览、更新回执、单游戏查询、帮助均有独立版式
- @ 操作人改用官方 `<qqbot-at-user>` 标签（官方适配器发送时会丢弃普通 At 组件）
- 昵称 / 别名中的 Markdown 特殊字符自动转为全角，防止破坏排版

依赖 AstrBot qq_official 适配器的原生 Markdown 发送能力（平台配置 `use_markdown`，默认开启；发送被拒时适配器会自动回退纯文本）。腾讯已将自定义 Markdown 开放给所有机器人的单聊/群聊场景，无需申请模板。如需关闭本插件的 Markdown 排版，在插件配置中关掉 `markdown_enabled` 即可。

#### 快捷指令按钮

默认在每条 Markdown 回复底部挂载**自定义按钮组**（`md_buttons`，QQ 已全量开放，无需申请）：

| 🐻+1 | 🐻-1 | 🐧+1 | 🐧-1 |
|---|---|---|---|
| **合计+1** | **合计-1** | **📊 总览** | **📖 帮助** |

点击按钮直接发送对应指令（旧版 QQ 客户端不支持时会提示升级）。实现上通过 botpy API 直发 markdown + keyboard（AstrBot 适配器本身不支持挂按钮），发送失败自动回退普通 Markdown。

可选项：

- `md_button_template_id` — 如需使用 QQ 开放平台配置的**按钮模板**，填入模板 ID 后替代内置按钮
- `md_inline_buttons` — 消息内嵌 `<qqbot-cmd-input>` 链接式指令（默认关闭：手机端点击可填入指令，桌面端仅显示为蓝色文字；已有底部按钮时无意义）

### 合计推算（直接更新合计时）

`j+n` / `j-n` / `j=n` / 别名指令直接更新机厅合计后，插件会按分游戏数据**反向推算**：

- **有效期内（默认 2 小时，可配置）更新过的分游戏数据视为可信并保留**；两个游戏都可信时保留更新时间更新的那个
- 另一游戏用 `合计 − 可信值` 推算，标注「预计」并提示「该数据可能不准确」

  > 例：合计更新为 5 卡，当前有 2 小时内的中二数据 2 卡 → 舞萌自动变为「预计 3 卡」
- **没有任何可信分游戏数据时，合计优先全加在舞萌上**（超过单游戏上限时溢出到中二），太久远的旧数据保持不变
- 推算出的数据在总览和单游戏查询中都会标注 ⚠；之后一旦有人用 `mai+1` 等直接更新该游戏，标注即清除

回复示例：

```
✅ 14:20:05 更新成功
🧮 机厅合计：5 卡（2台 · 机均 2+）
🐧 中二节奏：沿用 3 分钟前数据（2 卡）
🐻 舞萌DX：预计 3 卡（该数据可能不准确）
```

总览排版：

```
🎪 机厅数据如下
━━━━━━━━━━━━
🐻 舞萌DX：预计 3 卡（1台 · 机均 3）
　⚠ 推算数据，可能不准确（2 分钟前）
🐧 中二节奏：2 卡（1台 · 机均 2）
　⏱ 5 分钟前 由 xxx 更新
━━━━━━━━━━━━
🧮 合计：5 卡（2台 · 机均 2+）
　⏱ 2 分钟前 由 yyy 更新
🏷 机厅别名：万达
━━━━━━━━━━━━
💡 j+1 加卡 · j-1 减卡 · mai+1 / chu+1 分游戏
📖 发送「排卡帮助」查看全部指令
```

## 配置

WebUI 插件配置页可调整（`_conf_schema.json`）：

- `default_max_cards` — 默认排卡上限（默认 30）
- `default_mai_machines` / `default_chu_machines` — 默认机台数（默认各 1）
- `fresh_hours` — 合计推算的参考数据有效期，小时（默认 2）
- `smart_match_max` — 智能匹配的消息长度上限（默认 30）
- `markdown_enabled` — QQ 官方机器人下使用 Markdown 排版（默认开启）
- `md_buttons` — Markdown 消息底部挂载内置按钮组（默认开启）
- `md_button_template_id` — 按钮模板 ID，填入后替代内置按钮（默认空）
- `md_inline_buttons` — Markdown 消息内附带链接式指令（默认关闭）

以上为全局默认值，聊天内的 `设置机台` / `设置排卡上限` 按聊天覆盖。

## 数据存储

数据保存在 `data/plugin_data/astrbot_plugin_maimai_queue/queue.json`，更新/重装插件不会丢失。

## 与 QFun 版的差异

- 「号主」权限改为 **AstrBot 管理员**（WebUI 中配置的管理员账号）
- 聊天隔离键由 `type:peerUin` 改为 `unified_msg_origin`，天然支持多平台
- KV 存储改为插件数据目录下的 JSON 文件
- 自身消息回流防护简化为：忽略机器人自身账号消息 + 回复签名文本（如「机厅数据如下」）不当指令
